# Changelog

Все заметные изменения. Числа в записях — замеры на живой выдаче, а не оценки.

## 1.1.2 — 24.08.2026

### Исправлено

**Страница замирала на 0,8 секунды** (`src/render.js`, `src/content.js`)

Замер на выдаче «iPhone 16», по три прогона на сторону — самая длинная задача:

| | Длительность |
|---|---|
| без расширения | 109–125 мс |
| 1.1.1 | 732 / 933 / 732 мс |
| 1.1.2 | 214 / 196 / 211 мс |

Причина: проход по карточкам чередовал записи в DOM с чтениями вычисленного стиля. Каждое такое
чтение заставляет браузер пересчитать стиль заново, и на полусотне карточек это складывалось в
почти секундное замирание — ровно в момент появления штампов. Причину доказал контрольный замер:
с включённым тумблером рисуется 24 штампа вместо 47, и задержка падала до 192 мс, то есть цена
росла вместе с числом штампов.

Три изменения:

- тема страницы (`pageIsDark`) считается **один раз за проход**, а не на каждый штамп и каждый ряд.
  Она обходит всех предков `body` через `getComputedStyle`, и таких обходов было под сотню подряд;
- проверка опоры для штампа (`position: static`) вынесена в отдельную фазу чтения **до** всех
  записей, а однажды проверенная карточка больше не перечитывается;
- вместо своего `<style>` в каждом Shadow-хосте — один общий разобранный лист
  (`adoptedStyleSheets`) с откатом на `<style>`, если не поддержано.

Сам проход разложен на три фазы: вычисления без единой записи → пакет чтений → только записи.
Оставшиеся ~90 мс сверх фона — создание полусотни узлов, линейно числу карточек.

**Счётчик скрытых лёг поверх фильтров** (`src/render.js`, `src/page.css`)

Плашка «Скрыто: N · показать» висела фиксированно в левом нижнем углу и перекрывала колонку
фильтров. Переносить её вправо бессмысленно — там кнопка чата, поменяли бы одно перекрытие на
другое. Теперь плашка не парит, а встаёт полосой **над** списком выдачи, как родная плашка
«Выбраны фильтры… Отменить». Вставляется соседом перед контейнером списка, а не внутрь него:
внутри она стала бы элементом чужой сетки и карточки поехали бы.

**Кнопка «вернуть» гасла вместе с карточкой** (`src/page.css`)

Гашение просмотренного применялось ко всей карточке целиком, включая единственный интерактивный
элемент. Контраст плашки «уже смотрели · вернуть» падал примерно до 2:1 при норме 4,5:1 — человек
не видел, чем отменить. Теперь карточка помечается только обесцвечиванием, без прозрачности:
контраст плашки 7:1, а карточка по-прежнему читается как просмотренная.

**Штамп налезал на родную метку «Просмотрено».** Закрыто регрессионным тестом.

### Проверено

Живая выдача 24.08.2026, отдельный профиль браузера, расширение одно. Штампы: 45–50 карточек из 50.
Перезагрузка при постановке фильтра — ровно одна, шторма нет ни с включённым тумблером, ни без.
Прокрутка: 6 мс на кадр, ни одного кадра хуже 100 мс. Все регрессионные фикстуры зелёные.

### Открыто

- карточка, которая одновременно перекуп и уже просмотрена, вживую не попалась;
- профиль с большой историей просмотров (сотни отметок) не проверялся: гашение там применяется к
  десяткам карточек сразу.

## 1.1.1 — 23.08.2026

### Исправлено

**Шторм перезагрузок** (`src/content.js`)

`refreshPage` дёргается из трёх мест: из `boot`, из debounce-наблюдателя и из settle-таймера.
Навигация не мгновенная, поэтому каждый вызов успевал позвать `replace` заново.
Замер: **206 перезагрузок за 14 секунд**. Правка: флаг `navigating` плюс таймаут-страховка,
снимающая флаг, если навигация так и не произошла.

**Вечная перезагрузка, если раздел не держит параметр** (`src/content.js`, `src/config.js`)

Если раздел выкидывает `user=1` из адреса (например, аренда квартир), расширение ставило его
снова — и так по кругу. Правка: `MAX_FILTER_TRIES = 2`; после двух неудачных попыток работаем
только гашением на клиенте, без перезагрузок. Стало 2 попытки вместо 206.

Оговорка, которая остаётся в силе: счётчик попыток живёт в `sessionStorage`. При его отказе каждая
загрузка снова видит ноль — на стенде вышло `[1,1,1]`. И ключ завязан на `pathname|q`: если
канонизация меняет ключ, бюджет начинается заново. Живой регрессии не показано, но безусловной
гарантии здесь нет.

**`default_title` в манифесте** — было «Чистая выдача для Авито» при имени «Авито Помощник».

### Открыто

- раздел без такого фильтра (аренда квартир) вживую не проверен: площадка показала капчу;
  именно этот случай закрывает гард `MAX_FILTER_TRIES`;
- логотип повторяет четыре точки площадки. Для себя нормально, для публикации в Chrome Web Store
  это почти гарантированный отказ по товарному знаку.

## 1.1.0 — 21.08.2026

Первая рабочая версия. Ключевая находка: пустой экран лечится не клиентом, а **родным серверным
фильтром площадки** — параметр `user=1` в адресе выдачи. Но под «Частными» площадка всё равно
показывает магазины, поэтому поверх родного фильтра работает свой критерий перекупа.

Живой замер: из 50 карточек по запросу «iPhone 16» **47 оказались магазинами**, медиана продавца —
868 отзывов, ни одного продавца с 20 отзывами и меньше.
